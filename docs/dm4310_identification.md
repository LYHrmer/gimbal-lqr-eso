# DM4310：从 MIT 日志到每轴模型

[辨识总览](system_identification.md) · [MIT 协议接入](dm4310_integration.md) · [空日志模板](../examples/dm4310_identification_template/README.md)

**第一版优先采用 MIT 纯力矩通道，在已稳定的受限外环中采集数据；先离线拟合，再让 RLS 旁路记录候选参数。** 辨识对象是“这台电机与驱动 + 当前传动和负载”，不是所有 DM4310 共用的一组常数。本文提供采集与分析方案，尚无实机辨识结果，也没有实测 CSV 一键拟合程序。

## 1. 先确认模式与量纲

主控已有稳定的位置/速度外环时，MIT 报文使用 `Kp=Kd=0`，外环输出作为 `t_ff`；同时限制位置、速度、加速度及总力矩。这里的零增益关闭的是驱动内部 MIT 阻抗项，外部稳定控制仍然运行。[达妙 DM-J4310-2EC V1.1 手册，第 7 页](https://files.seeedstudio.com/products/Damiao/DM-J4310-en.pdf#page=7) 给出了该电流环结构；本库 [dm_mit_encode_torque()](../src/dm_mit.c) 实际按此编码。

开始采集前读回并记录实物型号后缀、驱动固件、模式、CAN/Master ID、`PMAX/VMAX/TMAX`、驱动失联超时，以及能读到的力矩常数/传动配置。**协议映射 `TMAX`、电机能力和本次实验限额是三个不同的量。** 官方 SDK 的型号默认表只能交叉核对，不能代替实物配置。[固定版本官方 SDK](https://github.com/dmBots/motor-sdk/blob/0b2ede457bdbf0882e29ab9958ab8fda047b7f4a/Python%E4%BE%8B%E7%A8%8B/u2can/DM_CAN.py)

| 日志量 | 可以从哪里获得 | 辨识时如何解释 |
| --- | --- | --- |
| 编码前请求 / 受限命令 | 主控外环及限幅器 | 用于检查参考与限幅，不直接当作已执行输入 |
| `command.torque_wire_nm` | 本库编码器从最终报文反解 | 包含量化的名义命令；发送成功仍不等于电机已经执行 |
| `feedback.position_rad / velocity_rad_s` | MIT 的位置 16 位、速度 12 位字段 | 先核对符号、传动比、角度跳变及与采样时刻的关系 |
| `feedback.torque_nm` | MIT 的转矩 12 位字段 | 在日志中命名为 `torque_estimate_nm`，按驱动电流模型的转矩估计处理，不能当作轴端扭矩传感器读数 |
| 状态、MOS/电机温度 | 同一反馈帧的状态与温度字节 | 保存原状态，按实物固件决定样本和运行是否有效 |

字段布局依据 [手册第 9–10 页](https://files.seeedstudio.com/products/Damiao/DM-J4310-en.pdf#page=9) 和上述官方 SDK；本库解析器保留原码和解码结果。公开协议把 `T` 称为转矩，没有给出你这版固件完整的内部估算与滤波算法；应向厂商核实其电流/力矩比例并通过已知负载校验，不能假定 `T` 是独立测得的真实轴端力矩。MIT 常规反馈帧也没有电机采样时间戳、独立相电流或母线电压字段，这些不是本模板的必填测量。

**力矩标度尚未校准时也能开始辨识，但只能报告有效模型。** 若选定日志输入为 `u`，实际力矩近似为 `a_u u`，则

```math
a_u u = J\ddot q+B\dot q+F_c\tanh(\dot q/v_c)+\tau_g+\tau_0.
```

此时数据可支持 `J/a_u、B/a_u、F_c/a_u` 等组合，不能独立求出 `a_u` 和绝对惯量。命令输入还包含电流环与通信动态；转矩回读也有标度、滤波和时序误差。选其中一种作为标签并声明假设，另一种用于一致性检查，不逐点混用。需要绝对参数时，可用已知力臂/负载的多点、双方向静态校核补充标度证据，并记录摩擦与传动损耗的不确定性。

未确认标度的归一化系数不能直接填入声明物理单位的 `inertia_kg_m2 / damping_nm_s_rad` 并称作实测物理参数；先保持明确的有效模型与输入标度，再决定如何进入控制设计。

## 2. 主控实际需要记录什么

使用 [空 CSV 与元信息模板](../examples/dm4310_identification_template/README.md)。按事件记录发送提交、可获得的发送完成、每次接收、每次控制计算及重力姿态更新；保留实际时钟计数，之后再对齐，避免把最近一次回读误当成当前周期的新采样。

- RX 保存原始 CAN ID、帧标记、DLC、8 字节载荷及解码结果；解析失败也保留载荷和失败标志。完整载荷可以重新解析位置/速度/转矩原码，因此模板未重复设置三个原码列。
- TX 保存序号、最终载荷、编码前后力矩和提交结果。`HAL_OK` 仅表示驱动受理，最多支持命令代理输入；无法获得发送完成时间就留空，不以提交时间冒充。
- CONTROL 记录本次真正送入控制器的参考、`actual_dt_s`、限幅和执行/跳过状态；源参考可能被限幅或丢弃，不能只记录源更新。另保存父轴是否固定、装配和载荷；温度从已有反馈读取，缺失量留空。
- 主控接收时间是**收到反馈的时间**，不是驱动内部测量时间。固定延迟、抖动、重复/缺失帧和驱动滤波都进入后续不确定性分析。

提交失败或发送状态未知的区间，不能把本次命令当作已施加输入，也不能武断地把实际输入填成零；标记输入未知，保留故障记录，并暂不纳入有效机械辨识窗口。即使有发送完成事件，也仍需考虑驱动执行延迟和内部限流。

模板使用 `host_tick / gravity_source_tick`，元信息声明时钟来源、单位、分辨率、计数位宽和回绕/复位处理。若只有 `HAL_GetTick()` 的 32 位毫秒计数，就记录毫秒原值；乘以 1000 不会得到微秒精度。使用真实微秒计时器时再声明相应单位。回绕可以按已声明规则展开，重启则分段，不能与上一段直接积分。

**从旧整车工程借用驱动时要另做核对。** 本次检查的原 Rudder 工程中，DM 支路用于拨弹；MIT 解码存在 MAX/MIN 实参倒置，部分 getter 对应状态未随 MIT 回读更新，且只解了一路温度。它不能直接充当云台辨识的正确测量源。本文两路温度、原码与转矩估计字段对应公开库 `dm_mit_feedback_t`，不表示旧整车已经具备相同记录能力。

## 3. 按轴安排实验

先完成方向、限位和失联停机检查，并获得可稳定保持/缓慢运动的保守外环。可以沿用已有调好的 PID 基线；不要用尚未辨识的示例 LQR 参数直接开展裸力矩激励。把本次限额、参考频段、幅值和持续时间写入元信息，再逐级增加激励；本文不预设适用于所有机构的力矩或频率。

| 阶段 | 操作 | 主要辨识量与检查 |
| --- | --- | --- |
| 静止与缓慢往返 | 父轴固定，多个位置双向接近，记录静止及缓慢运动 | 零位、符号、量化、噪声、死区与摩擦滞回 |
| Yaw 双向多速度 | 在已验证行程内改变速度，分别取正/反向近匀速片段 | `B、Fc、偏置`；一个方向或一种速度无法区分这些项 |
| 小幅动态激励 | 外环内加入独立的多频参考或受限附加力矩，记录实际发送输入 | `J` 和目标频带动态；保留加减速信息，避免只有匀速或只看稳态 |
| Pitch 多姿态与往返 | 在校准重力倾角下重复双向接近/慢扫，再做小幅动态实验 | 先分离重力、偏置与摩擦，再估计 `J/B` |
| 独立重复 | 改变参考相位/轨迹，覆盖计划使用的姿态与载荷 | 验证模型适用范围，保留一整次未参与拟合/整定的测试 |

采样率按实际有效反馈确认；最高激励频率须低于可靠采样、执行器与机构允许的带宽。出现振动、明显饱和或反馈异常时停止扩展激励，保留原记录及原因。频率、幅值与分段规则由基线试验确定后冻结；不能只保留拟合漂亮的片段。

Yaw 第一版可用 `J*q_ddot+B*q_dot+Fc*tanh(q_dot/vc)+tau0`，前提是父轴固定、Yaw 轴近似竖直且相应重力影响可忽略。连续 Yaw 需要可靠展开关节角；**`PMAX` 是协议映射端点，不能据此猜测实物位置的回绕周期**。若有额外传动，先实测 `q` 与电机输出角的比例，参数统一到同一个关节坐标。

角度与力矩必须配对变换。例如 `q=r*theta_m+q0`，`r` 含方向，则理想功率一致要求 `omega_q=r*omega_m`、`tau_q=tau_m/r`；效率和摩擦另建模或计入不确定性。先确认 MIT 位置与力矩已对应哪个输出端，避免重复计算内置减速比。模板保留电机回读/命令的原坐标：拟合前统一转换，或始终在同一个电机端坐标拟合，不能把已转换的关节角与未转换的电机 Nm 混用。

Pitch 同时保存机械关节角 `q` 和重力倾角 `theta_g`：本库约定重力倾角水平为零、抬头为正。只有基座固定、轴向与零位关系已校准时，才可用 `theta_g=q+theta0`。机械限位依据关节角，重力模型依据倾角，不能用设置电机零点代替两者的标定。[Pitch 接口](pitch_integration.md)

```math
\tau_g=g_c\cos\theta_g+g_s\sin\theta_g.
```

`gc/gs` 允许有符号；双向接近同一角度有助观察静摩擦造成的保持力矩差。窄角度区间中 `cos(theta_g)` 与常量偏置可能近共线，不能强行同时解释所有系数；重力角零位与 `gc/gs` 的相位也不能无约束地重复拟合。必要时固定独立标定项或缩小模型。

## 4. 离线最小二乘先得到候选

先按来源时间对齐，分段处理断流、重启、模式切换和角度展开失败；保留原始数据。若使用低通，记录滤波器及延迟，对回归方程各项采用一致处理；不能只把速度滤得很平滑，再与未对齐的力矩直接配对。

对每个有效积分窗口，构造线性回归：

```math
\int \tau_{label}dt =
J\Delta\omega+B\Delta q+F_c\int\tanh(\omega/v_c)dt
+g_c\int\cos\theta_g dt+g_s\int\sin\theta_g dt+\tau_0\Delta t.
```

这里的 `tau_label` 只有经过标度确认和动态假设检验后才能按物理力矩解释；否则系数按上一节的归一化模型报告。`vc` 先固定，Yaw 删除不需要的重力项；Pitch 可先离线固定重力与摩擦，再只求 `J/B`。用列归一化后的 QR/SVD 最小二乘检查秩与条件性，不直接求正规矩阵的逆。

积分能减少直接差分加速度的噪声，但不消除测量误差和闭环相关偏差。窗口过长或恰好覆盖完整周期可能丢掉惯量信息，邻接窗口也可能共享带噪端点。稳定外环中的独立参考/注入可用于设计 IV 或预测误差方法，但其统计条件仍需检查；**本仓库尚未实现实测 IV/PEM 或 CSV 拟合器**。

## 5. 在线 RLS 与控制整定怎样接上

| 工作 | 现在可用 | 仍需补齐 |
| --- | --- | --- |
| MIT 数据编解码 | [dm_mit.h](../include/dm_mit.h) 与对应 C 实现 | 板级收发、上述事件日志和时序校准 |
| 候选参数递推 | [独立 C RLS](../experimental/online_rls/README.md)，无效/无激励时冻结参数与 P | 实测窗口构造、板端激励判断及采用流程 |
| 名义 LQR 求解 | [tune_lqr.py](../tools/tune_lqr.py)，输入已确认的 `J/B/dt/Q/R` | 联合选择 ESO 带宽、Ki、模型不确定范围与硬件验收 |
| 接入配置 | `inertia_kg_m2`、`damping_nm_s_rad`、`coulomb_nm` 和 Pitch `gravity_cos_nm/gravity_sin_nm` | 实测参数审核与对应工况标记；现有参数头仍为仿真示例 |

当前 RLS 合成脚本的 20 ms 窗口、归一化比例和激励阈值是实验设置，不是 DM4310 实机默认值。实测第一版只旁路估计 `J/B`，先固定已校验的已知项；按有效更新间隔解释遗忘因子。RLS 小残差或小 P 不证明参数正确，也不自动决定控制增益。[递推估计的算法条件](https://www.mathworks.com/help/ident/ug/algorithms-for-online-estimation.html)

将数据按完整运行划分为辨识、整定验证和最终测试。冻结模型、滤波、基线及门槛后，先核对独立轨迹的预测/自由仿真、残差和目标频带，再在相同对象、参考及力矩约束下比较实际 C 控制器的误差、力矩波动、饱和与恢复。候选通过后在停止控制、明确重新初始化时换入配置；**当前没有运行中热更新增益的实现**。

## 一拖四与三轴的后续路径

一拖四须按实际板卡/固件重新核对命令、反馈的电流或转矩原码、比例、ID 和失联行为，建立独立的“命令 → 电流/估算转矩 → 关节运动”标度与动态模型。本库没有该模式的适配器，不能复用 MIT 的 `TMAX` 解码并宣称已经接入；物理辨识步骤可以复用，协议标度和采集层必须另做。

大 Yaw、小 Yaw、Pitch 先分别取得其他轴固定时的条件模型。父轴运动后，小 Yaw 的惯性项与末端绝对运动有关，摩擦与相对关节运动有关，需要追加耦合辨识与独立验证；三个单轴拟合成功不能证明三轴协调控制已经完成。
