# 参数敏感性与双电机验证

这里区分三类证据：厂商规格、明确命名的开源整车配置、尚未实测的工程假设。完整出处见 [parameter_sources.md](parameter_sources.md) 和 [parameter_sets.json](../sim/parameter_sets.json)。仅有“RoboMaster 云台”或电机型号，不能确定负载 J/B、摩擦、时延或噪声；本项目没有把假设矩阵解释为正常云台参数的概率分布。

`sim/run_sensitivity.py` 固定控制器名义 `J=0.039 kg·m²`、`B=0.30 N.m·s/rad`、离散 LQR 增益、ESO 带宽 80 rad/s 与补偿系数 0.8，再改变真实被控对象。原版 C 和新版 C 始终接收同一个场景、轨迹和随机种子；没有按真实惯量重新调参。1 ms 控制周期、2 s 光滑启动、6 s 总时长、2–6 s 指标窗口保持一致。

初始矩阵有 24 组，覆盖频率/幅值、J/B 相对倍率、测量噪声、0–10 个周期命令延迟、执行器力矩滞后、3/7 N.m 限额和有来源的整车参数。初跑发现这 24 组中速度相关包络均未触发，于是保留全部原场景，额外增加一对 4 Hz / ±20°、7 N.m 的有/无速度包络边界测试，共 26 组。增加这一对是为了实际验证物理限幅影响，没有删除原矩阵中的退步或饱和结果。

```bash
python sim/run_sensitivity.py
```

需要先构建共享库并获取固定版本原版源码；已有本地源码时加 `--upstream-source /path/to/YAW_Auto_Controller`。输出放在 `results/robustness/`，包括完整 JSON、CSV 表、矩阵图，以及基准与相对退步最大场景的跟踪图/压缩轨迹。新控制器的锁存故障会继续以 C 内核返回的零命令演化被控对象并被记录，不会用“触发故障”作为删除困难工况的理由；数值非有限则明确记录失败。

DM4310 的包络是依据规格点构造的简化模型：驱动方向连接假设的 `(0 rpm, 7 N.m)`、规格额定点 `(120 rpm, 3 N.m)`、空载点 `(200 rpm, 0 N.m)`，再施加独立的 3 或 7 N.m 力矩上限。零速 7 N.m 只是把 peak 规格放到截距的假设，未被确认是堵转力矩。制动方向只加电流对应的力矩上限，未建模回馈母线、供电吸收能力与温度。3 N.m 上限不代表任意转速下可以无限持续输出；7 N.m 场景没有验证允许的峰值持续时间。

包络在每次 RK4 求值时施加到执行器力矩动态的输入。结果分别报告控制器命令达到上限的比例、执行器包络实际限制的控制周期比例和实际力矩峰值，不能只看其中一个量。2/5 ms 一阶力矩滞后是假设；实际电流环、CAN 延迟和电压变化仍需测量。

这里的反馈是“假设完成校零后”的零中心均匀间隔量化，并叠加同种子噪声。它不是逐 bit 的 CAN 反馈回放；特别是 DM MIT 的奇数区间原始映射中，物理零点位于半个量化间隔。双电机实验中的命令则确实经本仓库 C 编码器转换为 wire torque，再进入执行器模型。

结果 JSON 同时记录固定 DLQR 的离散线性反馈环诊断：包含真实 J/B、假设的一阶执行器滞后与整数命令延迟，计算增益交越频率、相位裕度、增益裕度、附加延迟裕度和闭环谱半径。这是理想 PD/状态反馈参考模型，不包含积分、速度误差滤波、ESO、摩擦、噪声、前馈或限幅非线性；尤其不能把它当成最终带积分 GM 配置的实际闭环裕度。“反馈环带宽”也不等同于完整闭环的跟踪带宽。它们用于比较时延和参数变化的方向，不能充当完整系统或硬件的稳定性证明。

`sim/run_motor_profiles.py` 读取 [DM4310 配置](../profiles/dm4310_24v.json) 与 [GM6020 电流模式配置](../profiles/gm6020_current.json) 的完整参数。两者使用相同的假设负载 J/B、固定外力矩 +0.15 N.m 和平滑库仑摩擦 0.06 N.m，但保留各自规格限额、传感器量化和命令协议。GM6020 以官方 `Kt=0.741 N.m/A` 及当前模式命令映射进行 C 编码；没有把旧的电压命令当成电流命令。配置中 current mode 的确认只是离线仿真的前提，不会打开真实驱动模式或发送 CAN。

GM6020 的驱动包络使用手册 320 rpm 空载转速与 156 rpm/(N.m) 梯度形成的直线，其零速截距 `320/156 N.m` 是模型推算值，不是厂商 peak 规格。应用力矩上限为 1.2 N.m；手册另列持续堵转力矩 0.86 N.m，因此仿真中低速/换向时接近 1.2 N.m 的短过程不构成热可行性验证。手册 3 ms 是机械时间常数，不能被当成电流环时间常数。

```bash
python sim/run_motor_profiles.py
```

所有四个预定轨迹 `1 Hz/±5°、2 Hz/±5°、3 Hz/±5°、3 Hz/±10°` 都保留。主要可达工况在看结果前固定为 **2 Hz / ±5°**：每种电机各跑开发种子 `4310–4314`，配置冻结后再跑未参与选择的验证种子 `4315–4319`。每个种子内原/新控制器配对，记录 RMSE、最大误差、命令 RMS、实际力矩、软件/执行器限幅和故障。报告均值、最差变化和每一个种子，不只给最优结果，也不以五个合成种子制造置信区间的精确感。

最终 GM 配置的慢积分使用 `Ki=2*Kposition`、积分力矩上限 0.2 N.m、回算速率 2 s⁻¹，速度误差滤波关闭。它用于消除 `eso_gain=0.8` 留下的恒外扰残差。报告同时保留原版 Ki0 基准、相同 Ki 的原版 C、新版完整配置三列；新增积分带来的收益属于配置优化，不能归因为纯内核算法优势。同参数 Ki0 的 GM 比较没有显示稳定 RMSE 优势，相关开发结果保留在 `results/development_checks/`。

开发检查中，GM 的 J×0.75、J×1.25、5 ms 命令延迟及三倍测量噪声都改善了相对 Ki0 基准的 RMSE；10 ms 延迟却从约 0.0580° 恶化至 0.1032°。3 Hz / ±10° 力矩受限工况也略有退化。进入饱和后经导数一致的 C2 轨迹切回主工况，4–8 s 恢复 RMSE 为原 Ki0 约 0.0254°、原相同 Ki 约 0.0190°、新版约 0.0168°。这些结果支持所测低延迟可达域内的配置选择，不支持全工况更优的断言。

比较结论应限定在同一种电机内的原版与新版；GM/DM 之间的绝对误差差异同时受到力矩能力、传感器量化、配置限额和协议的影响，不能用来量化控制算法优劣。全部结果仍为 synthetic，正向软件变化需要后续台架验证，退步和受限边界也应保留供选型与调参使用。

最终独立验证种子 4315–4319 中，DM 与 GM 相对明确 Ki0 基准各有 5/5 个种子降低 RMSE，平均配对降低分别为 6.90% 和 33.68%。GM 同积分原版对照却显示新版平均相对 RMSE 高 4.00%，因此不能据前面的 33.68% 宣称纯内核实现更准。完整成本指标、第三列调参对照与每个 seed 见 [双电机结果](../results/motor_profiles/README.md)。26 组固定 Ki0 的 DM 敏感性中仍保留了 J×0.75 时约 7.84% 的退步，以及 4 Hz / ±20° 包络限制边界；没有把这些结果从验证材料中删除。
