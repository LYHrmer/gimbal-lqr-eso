## 1. 项目概述与代码对应

在 STM32F407 + FreeRTOS 的 RoboMaster 步兵云台上，开展基于惯量/阻尼模型的 LQR + LESO 力矩控制改造，建立离线增益设计、合成仿真回归和上机消融调试流程。此次源码保留了为排查超调而关闭补偿的中间状态，硬件性能 A/B 尚待完成。

| 范围 | 已核对内容 |
| --- | --- |
| 历史整机工程 | README 列出 STM32F407 C 板、BMI088、GM6020×2；CMake 使用 C++17、Cortex-M4F 和 CMSIS-DSP；任务代码使用 FreeRTOS |
| 历史控制与辨识 | `Utils/MotorRLS.cpp`、`user/algorithm/src/LQR.cpp`、`user/algorithm/src/ADRC.cpp`、`user/application/src/gimbal.cpp` |
| 历史 Python 实验 | `tools/pitch_lqr_eso_sim.py`：ZOH/DARE、两轴仿真、前馈消融、惯量/延迟/噪声扫描、异常周期检查 |
| 本公开库 | 独立 C11 控制库及 STM32 示例；[Python 调用实际 C 内核](../sim/c_core.py)的合成仿真，与上述 Python 重写的整机模型是两个实现范围 |

整机的两轴使用 GM6020；README 中的 DM4310 属于拨盘，不能将它列成这次云台测试电机。CAN 发送路径为 Yaw：CAN1、`0x1FE` 第 2 槽；Pitch：CAN2、`0x1FE` 第 1 槽。源码采用电流命令，实物驱动固件及模式没有现场核验。

## 2. 代码已经实现的内容

**模型与 RLS。** `MotorRLS.cpp` 用约 20 ms 积分窗口和梯形积分形成 `∫τdt = J·Δω + B·∫ωdt`，避免直接差分角速度；遗忘因子为 0.99。其输出是候选 J/B，受力矩标度、摩擦、重力和激励影响。该文件只有一个全局估计器，不能同时给两轴维护独立状态；此 ZIP 的两处 `UpdateRLS()` 调用均被注释。它支持“实现了在线辨识模块”，不支持“此版本正在双轴在线辨识并自动更新增益”。

**离散 LQR。** Python 用 `expm` 对连续模型做精确 ZOH，再用 `solve_discrete_are` 求增益；C++ 实时链路使用常数增益表。`Lqr::Calc()` 实现独立积分力矩上限、幅值限制→斜率限制→再次硬限幅，以及 `−expm1(−rate·dt)` 反算抗饱和；Ki=0 时积分输出和内部积分均置零。

**LESO。** `LESO::Update()` 使用预测—校正结构，第三状态为残余扰动力矩 N·m，扣除已知阻尼并纳入已知重力输入；固定周期、无约束的名义观测误差极点设计为 `exp(−ω₀h)`。代码包含非有限输入检查、周期窗口、首次播种及扰动/补偿幅值/补偿斜率限制。3 rad/s 高角速度分支保持 z1/z2/z3 和补偿，只更新上次速度，不继续位置预测。

**周期与模式。** LESO 使用自己的 DWT 间隔；LQR 的 `YawLoopStep()/PitchLoopStep()` 对越窗间隔回退为名义 1 ms。模式切换有状态和计数复位。源码证明这些路径存在，不能替代实测周期分布；异常周期下 LESO 返回失败也没有使整条电机输出链停止。

## 3. 必须区分配置常量与实际生效分支

在 ZIP 的 `gimbal.cpp` 手动分支（约 237–306 行），实际状态是：

| 功能 | 该版本实际执行 |
| --- | --- |
| 两轴 LQR | 开启，Ki 均为 0 |
| 两轴目标速率前馈 | 计算后立即被 `SetVel(0)` 覆盖，实际关闭 |
| Yaw LESO | 仍调用 Update，但 `Calc(yaw_dt, 0)`，补偿没有进入电机命令 |
| Pitch LESO | Update 被注释，没有推进 |
| Pitch 重力前馈与 LESO 补偿 | `pitch_extra_torque = 0`，实际关闭 |
| 在线 RLS | 两轴调用均被注释 |

因此常量 `comp_gain=0.8` 不能证明此版本开启补偿；该包更符合用户描述的消融排查阶段。自瞄仍走独立的惯性/阻尼/摩擦及加速度控制支路，不能写成手动、自瞄都已统一替换成 LQR + LESO。

Pitch 位置限制为 `[−35.5°,21°]`；`guard=1°` 用于在靠近端点时清除继续朝外的视觉速度/加速度，**没有将位置范围直接缩成 `[−34.5°,20°]`**。视觉速度/加速度限值 20/60 与手动前馈导数护栏 20 rad/s 属于不同路径，不能混称摇杆限速。反馈 gyro 低通为 80 Hz，目标变化率低通为 40 Hz，滤波器按 1000 Hz 初始化。

按源码权重 `Q=diag(400,1)、R=1、dt=1 ms` 复算，Yaw/Pitch 名义离散闭环谱半径分别为 **0.977511 / 0.978583**。Pitch 的位置增益相对相同数值 Q/R 的连续解 20 降低 **2.82%**，速度增益相对 1.15159239 降低 **2.48%**；原文“约 2.8%”应具体指前者。较硬 Yaw 候选 `Q=diag(1600,1)、R=0.2` 可复算得到 `85.483794 / 2.997889`；其高频抖动来自代码注释及用户上机回顾，没有时序日志。

谱半径只描述名义无约束二状态模型，不能证明含观测器、滤波、延迟、限幅的完整环路具有实机稳定裕度。

名义电流换算 `16384/(3×0.741)=7370.22042285` 与常量一致；2.2 N·m 对应约 **2.969 A、16214.5 命令值**，约为协议幅值的 98.97%。它是应用命令上限，不能写成持续输出能力；官方 v1.4 手册列出最大连续转矩 1.2 N·m。[官方协议与规格](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E20231013.pdf#page=8)

若补偿通道接通，按 `−0.8·z3` 和 `|z3|≤0.8` 得到的补偿目标最大为 **0.64 N·m**，并非 1.0 N·m。实际周期 1 ms 时，总力矩/补偿每步变化上限分别为 0.5/0.1 N·m。这些是计算值，不是电机实测。

## 5. 已复现的历史仿真表

原表保存在 [reported_step_metrics.csv](evidence/gm6020_early_test/reported_step_metrics.csv)，本次精确结果及完整参数见 [step_diagnostics.json](evidence/gm6020_early_test/step_diagnostics.json)。六组主要指标可复现；Yaw 关闭补偿的峰值复算为 1.02149°，与原表 1.022° 相差约 0.0005°，下表统一按本次结果显示。

**关键条件：原脚本 `GYRO_LPF_CUTOFF = 82/100.0`，实际为 0.82 Hz。** 本表使用该原值；并不是固件的 80 Hz 反馈链路。

| 轴 / 延迟 | 补偿 g | RMSE | 全程峰值误差 | 超调 | 调节时间 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Pitch / 1 ms | 0 | 0.127° | 1.127° | 4.6% | 394 ms |
| Pitch / 1 ms | 0.8 | 0.552° | 1.226° | 18.8% | 窗口内未调定 |
| Pitch / 2 ms | 0 | 0.130° | 1.170° | 4.9% | 544 ms |
| Pitch / 2 ms | 0.8 | 0.712° | 1.302° | 26.0% | 窗口内未调定 |
| Yaw / 1 ms | 0 | 0.459° | 1.021° | 16.3% | 窗口内未调定 |
| Yaw / 1 ms | 0.8 | 2.021° | 3.752° | 74.5% | 窗口内未调定 |

这组结果的真实统计口径是：

- 名为 `step` 的参考实际在 **0–0.2 s 线性爬升到 5°**，随后保持，不是瞬时阶跃；总时长 2 s。
- 使用种子 1/2/3；J/B 无失配、扰动倍率 1.3、角度噪声 0.01°、2 ms 执行器滞后，以及脚本的 500 Hz 保持/量化模型。
- **积分开启**，Yaw Ki=10、Pitch Ki=20；Pitch 的重力模型和已知重力前馈也开启，未实现固件的高角速度冻结。
- RMSE 统计 **0.8–2.0 s**；峰值误差统计整段，最后对种子取均值。脚本的补偿 RMS、限幅占比和峰值力矩只保留最后一个种子，不是三次统计均值。
- 调节带为 ±0.25°，从参考到达 5° 的 0.2 s 开始计时；脚本返回 1800 ms 表示观察上限，不能写成已经在 1.8 s 收敛。

结果 JSON 同时保存 12 组条件的 **36 次逐种子指标**。`metrics` 保留原脚本的统计方式；`trials` 明确标记每次是否触及调节时间观察上限。只要一个种子未调定，`settling.mean_ms_if_all_settled` 就为 `null`，避免将截断后的均值当成收敛时间。本次所有未调定条件均为三个种子全部未调定，没有混合状态被均值掩盖。

在上述固定模型中，开启补偿导致退化成立；其原因不能直接推广为“实机高带宽 LESO 必然恶化”。`g=0.8` 应称“开启补偿”，不是 `g=1` 意义的全增益。

保持其余脚本设置不变，仅将模块中的截止频率改为固件常量 80 Hz（不改原文件），得到：

| 轴 / 延迟 | RMSE：g=0 → g=0.8 | 峰值误差：g=0 → g=0.8 | 超调：g=0 → g=0.8 |
| --- | ---: | ---: | ---: |
| Pitch / 1 ms | 0.0793° → 0.1144° | 1.6541° → 1.5238° | 3.41% → 5.11% |
| Pitch / 2 ms | 0.0793° → 0.1146° | 1.6537° → 1.5242° | 3.43% → 5.12% |
| Yaw / 1 ms | 0.4226° → 0.1774° | 1.2772° → 1.6974° | 13.04% → 5.25% |

Yaw 的 RMSE 改善方向发生反转，同时峰值误差仍增加；Pitch 的 RMSE 仍退化。这说明滤波参数和指标口径会实质影响结论。**80 Hz 对照只是单变量敏感性检查，仍未复现此 ZIP 的 Ki=0、补偿关闭、冻结与整机执行路径，不是新调好的配置。**

原脚本两轴默认扫描（`--seeds 3`）本次退出码为 **1 / FAIL**；原样输出见 [simulation_as_received.log](evidence/gm6020_early_test/simulation_as_received.log)。原回归门槛包括无积分标称阶跃超调 ≤20%、±5% 调节 ≤250 ms，甩杆前馈开启后超调 ≤1%、收敛 ≤300 ms；不能因名义 LQR 极点合格就忽略这些失败。本次没有运行 `--full` 网格，也没有把脚本存在的用例写成全部验收通过。

## 6. 异常周期结果的准确表述

`observer_period_regression()` 对 20/50 ms 周期得到“旧形式 inf，新形式越窗”的输出，但有两个限制：

1. 旧式欧拉递推遇到 `|z3|>1e6` **或**非有限数时，将记录变量设为 `inf`。输出不能区分越过阈值与真实 IEEE 浮点溢出；而且旧 z3 是该简化观测器的扰动加速度状态，不能与新 N·m 状态直接比幅值。
2. “新形式通过”只判断周期是否超出窗口，**没有调用 C++ LESO 或验证清状态后的恢复过程**。

源码的 `LESO::Update()` 确有越窗清状态并返回 false 的路径，补偿归零；因此可以写“实现了周期窗口保护，并用脚本覆盖 20/50 ms 越窗条件”。不能写“已经实机证明任意 ≥20 ms 抖动均安全”，也不能把 **LESO 补偿为零**扩展成整条电机命令为零。原工程 Release/RelWithDebInfo 使用 `-Ofast`，有限数防护还需在实际目标编译选项下验证。

## 7. 超调案例与尚未完成的结论

用户回顾称，大幅快速推摇杆后过冲并缓慢回摆约 1–2 s；关闭积分后仍有问题，关闭 LESO 补偿后 Yaw 消失、Pitch 减轻但残留约 0.5°。这是有价值的变量隔离思路；本次源码中的旁路与这种调试状态一致，但没有当时波形和重复次数，不能唯一确定根因。

`z3 += L3·innovation` 确有累加结构，模型误差和输入时序误差可能进入扰动估计。然而“接近稳态时线性模型可观测性变差”不是已证实解释：对 `[θ,ω,d]`、位置输出的常值扰动线性模型，观测矩阵行依次为 `[1,0,0]`、`[0,1,0]`、`[0,−B/J,1/J]`，行列式 `1/J≠0`，不随当前角速度降低而失去可观测性。

应保留的结论是“将排查范围缩小到扰动补偿与瞬态/限幅/时序的交互”。冻结全部状态可能使位置预测落后，解除冻结时产生创新尖峰；3 rad/s 阈值的作用及恢复行为仍待验证。

历史文字中的“甩杆过冲 5.5%→0.02%、收敛 1.3 s→0.2 s”没有在此次原样运行中复现，不能列为该包的实测收益或验收结果。公开库已有的 GM6020 Yaw −33.68% 等数值来自另外的[合成仿真与对照配置](validation_report.md)，同样不能移用到本页早期整机。

## 8. 复现方法与下一批数据

需持有用户提供的原 ZIP；本仓库只附核对脚本与结果，不包含整车源码。将 ZIP 解压为 `Rudder_Infantry_Gimbal` 后，在本公开库根目录运行：

```bash
python3 docs/evidence/gm6020_early_test/reproduce.py --source /path/to/Rudder_Infantry_Gimbal --output build/gm6020-early-test/step-diagnostics.json
python3 /path/to/Rudder_Infantry_Gimbal/tools/pitch_lqr_eso_sim.py --seeds 3
```

第一条检查原脚本哈希，复算原值和 80 Hz 对照的 12 组条件，并单独保存种子 1/2/3 的结果；第二条运行原默认回归，预计保留 FAIL。两者都只运行电脑端合成模型，不编译或烧录整机固件。本次环境版本保存在结果 JSON。

未持有 ZIP 时，可以检查仓库内证据的一致性：

```bash
python3 tools/check_legacy_gm6020_evidence.py
python3 -m unittest discover -s tests -p 'test_legacy_gm6020_evidence.py'
```

CI 同样执行这些检查：核对工况/种子覆盖、逐次指标与均值、原脚本的末种子力矩统计、未调定标记及原表精度内的一致性。检查通过只说明已保存的证据相互一致，**不表示重跑了私有源码、不改变原仿真的 FAIL，也不代表硬件验收通过**。

下一次硬件实验按[实机记录模板](test_data_recording.md)保存目标角、实际角、gyro、实际 dt、LQR/积分/重力/LESO 分项、最终 CAN 命令、原始电流反馈和配置/固件哈希。定位此问题另需 innovation、z3、限幅状态及冻结进入/退出事件。分别进行补偿消融和旧 PID/LQR 同轨迹 A/B，每种至少 3 次；统一统计窗口与调节带，保留失败运行。

**三条版**

- 在 STM32F407 / FreeRTOS 的 GM6020 双轴云台上实现 LQR + LESO 手动力矩控制链路，采用积分窗口 RLS 估计 J/B 候选，基于精确 ZOH + 离散 Riccati 设计反馈增益。
