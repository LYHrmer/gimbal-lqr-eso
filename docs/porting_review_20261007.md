## 核对到的接入差异

| 观察到的实现方式 | 对迁移的影响 | 本次公开项目处理 |
| --- | --- | --- |
| 整机为 C++17，控制器由内部类实现 | 设计在真实机构中使用，不等于公开 C ABI 已经上机；复制控制律会形成两个长期维护的实现 | 新增 `gimbal_add_to_target()`，让既有固件直接编译公开 C 源码；验证 C++17 调用与链接 |
| Pitch 使用宿主自定义重力曲线 | 仅从输出端加补偿会绕过总限幅/抗饱和；直接使用基础 Yaw API 又不包含 Pitch 机械限位 | 新增 `gimbal_controller_step_with_gravity()`，复用原机械检查与上一周期负载历史 |
| 控制坐标用姿态角，另有电机编码器；电机输出存在方向反转 | 机械限位角、世界姿态和重力角不能混作一个信号，符号不能在多层重复翻转 | 增加信号/单位/方向/来源时间映射表，曲线及具体安装参数留在宿主 |
| 目标速率计算后仍有无条件清零，Yaw 补偿计算后未进入输出 | 常量或计算语句存在并不等于该功能实际开启 | 记录模板要求逐轴核对实际调用路径和本轮功能开关 |
| 主控制周期异常时有回填名义值的分支，LESO 使用独立间隔 | 数值正常的回填值会掩盖真实空档，两个时间历史也可能不同步 | 移植说明要求传递真实 dt，沿用公开库锁存故障与显式恢复契约 |
| 辨识构建在已受限控制输出后叠加 PRBS，再夹幅；默认构建关闭辨识 | 激励后的总命令不再自动满足前级变化率约束，不能把它误接成被动重力负载 | 明确辨识输出所有权与标签时序；保留独立 opt-in 辨识边界，本次不移植私有辨识代码 |

这些是源码和接口契约核对，未据此宣称某项实机异常的唯一根因，也未重新调整用户机构的 J/B、增益、滤波或 LESO 带宽。

## 修改与验证

- `cmake/GimbalController.cmake`：附加到已有目标，不调用公开库顶层 `project()`，不带入主机测试/共享库；C11 源码与 C++17 宿主保持各自编译语言，支持 GM6020 或 DM4310。
- `include/gimbal_controller.h` / `src/gimbal_controller.c`：新增外部重力模型入口。公共结构布局、原函数签名和原默认计算路径保留；外部曲线必须显式关闭内置重力系数，重复配置会锁存配置错误。
- 回归覆盖：外部模型与等值内置模型的逐步输出一致；切换当前负载时 ESO 仍使用上一周期负载；总限幅、变化率、抗饱和、降额、机械越界、陈旧 pose、20 ms 周期、NaN/Inf 及复位暖机。
- C++17 独立工程分别链接两种电机协议，检查有限数编译保护和重复接入拒绝。所有 fixture 均为独立合成数值，不含整机源码或私有重力系数。

复跑命令及最终结果见 [验证记录](evidence/porting_review_20261007/validation.json)。全部软件检查通过也不等于该公开 C 库已在用户整机上烧录或完成性能 A/B。
