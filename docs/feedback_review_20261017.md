# 两轴反馈时序与 GM Pitch 诊断记录

本轮沿用 `e9d34ca` 的正式 C 控制器和全部 profile，补充测量链路的测试能力。
新增测试调用真实 C 控制器与电机命令编解码器，全部数据为**合成仿真**。
私有整机源码没有进入仓库；用户确认的 GM6020 Pitch 实机可用状态保持原记录。

## 本轮交付

- 两轴共享的采样器：角度/速度独立采样周期、相位、传输延迟、确定性延迟抖动、丢帧和乱序。
- 每次采样只生成一次噪声并量化，重复读取保持数值和源时刻；乱序旧包不覆盖新样本。
- 两轴逐样本日志追加位置/速度源时间，正式 API 继续使用两者中较大的年龄。接口、控制增益和固件计算不变。
- GM Pitch 固定条件消融，以及隔离编译的源时刻 ESO 候选。候选未通过筛选，未加入正式库。

修改前后，GM 的默认 Yaw 21 列、Pitch 23 列完整轨迹逐元素一致。旧列顺序不变，新增时间列只追加。
旧的周期/延迟参数仍可用；已有实验继续使用同步 1 kHz 新鲜反馈，完整回归结果另见本页末尾。

## 时序矩阵

每种电机、每个轴各 10 种时序 × 3 个开发种子 × 补偿开/关，共 **240 次试验**。
Yaw 为 2 Hz / ±5°，Pitch 为中心 +20°、1 Hz / ±5°；总长 6 s，评价窗口 2–6 s。
同一对照内 Ki、重力、增益、轨迹与物理模型一致，只改变 `eso_gain=0/0.8`。
Yaw 使用 4310–4312，Pitch 使用 5300–5302；均为已有开发种子，不是新的独立验证集。

保留此前同步周期/延迟组合 `(1,0)/(2,0)/(1,2)/(2,2)/(2,5) ms`，新增：

| 工况 | 位置通道 | 速度通道 |
| --- | --- | --- |
| 异步速率 | 周期 2 ms | 周期 1 ms |
| 异步相位与延迟 | 周期 2 ms，相位 1 ms | 周期 1 ms，传输延迟 1 ms |
| 传输抖动 | 周期 2 ms，延迟按 1/2/0 ms 循环 | 周期 1 ms |
| 丢帧 | 周期 2 ms，每第 2 次后续采样丢弃 | 周期 1 ms |
| 乱序 | 周期 1 ms，延迟按 3/0 ms 循环，丢弃晚到旧样本 | 周期 1 ms |

两个通道在 t=0 各有一份同步快照，之后才应用各自时钟。控制周期固定 1 ms；这里的抖动是测量传输抖动，**不包含控制任务周期抖动**。同种子跨采样频率不代表同一条连续时间噪声。

GM6020 的部分结果如下，单位 °，每格为三个种子的 RMSE 均值：

| 轴 / 工况 | 补偿关闭，仅观测 | 补偿开启 |
| --- | ---: | ---: |
| Yaw，同步 1 kHz | 0.02274 | 0.01622 |
| Yaw，同步 500 Hz | 0.02282 | 0.03673 |
| Yaw，角度 500 Hz / 速度 1 kHz | 0.01811 | 0.03346 |
| Yaw，传输抖动 | 0.06588 | 0.08435 |
| Yaw，丢帧 | 0.06984 | 0.09084 |
| Pitch，同步 1 kHz | 0.03920 | 0.02837 |
| Pitch，同步 500 Hz | 0.02954 | 0.02839 |
| Pitch，角度 500 Hz / 速度 1 kHz | 0.03459 | 0.03359 |
| Pitch，传输抖动 | 0.03724 | 0.05321 |
| Pitch，丢帧 | 0.03774 | 0.05451 |

216 次未超时运行完整结束；24 次预期超时均在 6 ms 锁存陈旧反馈故障。
其中 12 次 Pitch 在软件零输出后仍受重力作用，随后越过机械范围，仿真提前停止并保留失败。
这些部分轨迹不用于完整跟踪性能比较。没有将“脚本执行结束”或“保护被触发”写成性能通过。

完整四种轴/电机组合见 [时序指标](evidence/feedback_review_20261017/multirate.json)。
预先指定的 GM 异步首个种子两组波形也保留：[Yaw](evidence/feedback_review_20261017/yaw_gm_angle500_gyro1000.csv.gz)、[Pitch](evidence/feedback_review_20261017/pitch_gm_angle500_gyro1000.csv.gz)。其余工况保留指标，可用脚本重算。

## GM Pitch 开发组为什么没过

先重现原有三个实现：同 Ki 原版 C、新 C 关闭重力、新 C 开启重力。
原定门槛仍要求对两个对照都改善，不能在看到结果后换基准。
每次只取消一个物理/测量因素，结果为新 C 开启重力相对原版的平均配对 RMSE 变化：

| 单变量诊断 | 平均配对变化 | 改善种子 |
| --- | ---: | ---: |
| 原配置 | −1.41% | 1/3 |
| 仅去除测量噪声 | +2.62% | 0/3 |
| 仅去除位置量化 | +1.53% | 2/3 |
| 仅去除速度量化 | −6.22% | 3/3 |
| 仅去除命令延迟 | +0.52% | 2/3 |
| 仅去除执行器滞后 | −1.91% | 3/3 |

无噪声时三个种子产生同一确定性试验，不能算作三份独立证据。
速度量化步长为约 0.10472 rad/s；取消它后，新 C 重力开启 RMSE 均值从 0.02837° 降到 0.01404°。
但这时同内核的重力关闭对照约为 0.01402°，仍没有支持“两种对照均通过”的结论。
这说明量化会显著影响该开发组的结果；它没有证明实际陀螺仪具有相同分辨率，也没有证明量化是唯一原因。

另做 Ki、ESO 补偿、重力前馈的 2×2×2 开关试验，保留全部 24 次结果。
例如 ESO 与重力开启时，Ki=0 的 RMSE 均值为 0.02822°，原 Ki 为 0.02837°，关闭积分没有带来足以支持重新整定的优势。
这些开关试验只用于区分各项作用，不替代同 Ki 的原验收。
完整诊断共 78 次真实 C 调用试验，见 [诊断指标](evidence/feedback_review_20261017/pitch_diagnosis.json) 与 [原配置三实现波形](evidence/feedback_review_20261017/pitch_configured.csv.gz)。

## 源时刻 ESO 候选的决定

[隔离试验](../experimental/feedback_timing/README.md)显式携带位置样本年龄、是否为新样本及源采样间隔。
逐控制周期预测，仅在新位置样本到达时校正；使用常加速度近似回推延迟测量并向前传播校正量。
它没有历史输入完整回放，也没有对状态反馈另做时间对齐。

运行前规定：新鲜反馈与补偿关闭路径保持一致，各正常工况 RMSE/峰值平均配对退化不超过 5%，GM 两轴两种 500 Hz 工况至少改善 10%，不增加故障或越界。
结果：GM Pitch 同步 500 Hz 的 RMSE **+5.90%**，同步 500 Hz 加 2 ms 传输延迟 **+5.39%**；GM 目标工况也未达到改善门槛。
因此候选被拒绝，正式 C、接口和 profile 保持原样；没有继续按这些结果试选带宽或放宽门槛。

证据包括 [候选完整指标](evidence/feedback_review_20261017/candidate/metrics.json)、[筛选判定](evidence/feedback_review_20261017/candidate/assessment.json) 和可复现补丁。
这个结果只否定本次具体候选，不能推断所有多速率观测器都无效。

## 移植与复现

实际接入时分别保存位置、角速度的生产者时间戳/序号；重读缓存不能更新时间戳。
当前单一 `age_s` 应覆盖最旧输入。它用于新鲜度保护，不能代表两个量来自同一时刻，也不会自动补偿延迟。
若只有主控接收时间，就标明它是接收时间，并单独记录无法观测的传感器/传输延迟。
姿态融合的角度分辨率与 GM6020 RPM 反馈分辨率也要分开，不能因为电机型号相同就沿用同一套测量模型。
采集字段见 [补充记录模板](../examples/feedback_timing_record_template.md)。

```bash
python3 sim/run_multirate.py --output build/multirate
python3 sim/diagnose_pitch.py --output build/pitch-diagnosis
# 保留原失败门槛的复现命令，当前预期返回非零：
python3 sim/diagnose_pitch.py --output build/pitch-diagnosis --require-development-pass
python3 -m unittest discover -s tests -p 'test_feedback_timing.py'
python3 -m unittest discover -s tests -p 'test_multirate_candidate.py'
```

测试、来源与结果校验值见 [验证记录](evidence/feedback_review_20261017/validation.json)。
