# 算法、运行时代码与技术描述复核

本轮以 `ce4c203` 为基线，检查公开 C 内核的 LQR/ESO 数学、前馈与输出约束、测量时序和性能证据。正式变更是**保留首个故障原因、补充反馈时序仿真与技术边界**。控制模型、增益、默认带宽和 profile 未重新整定；私有整机源码未进入本记录。

[正式版本验证记录](evidence/algorithm_review_20261016/validation.json)：Release 与 ASan/UBSan 各 8 项 CTest（含可选 RLS）、64 项 Python 测试、8 个 Cortex-M4F 编译单元通过。Yaw 声明门槛和 Pitch 留出门槛通过；两轴原有性能指标与已发布记录一致，GM Pitch 开发组失败仍保留。源码、候选及结果哈希一并归档。

## 数学与实现核对

- LQR 工具对名义对象精确 ZOH 离散化，求解的是离散成本 `Σ(xᵀQx+uᵀRu)`。模型离散准确不等于连续成本也被精确离散；二状态谱半径也不包含 ESO、积分、执行器延迟或限幅。
- 残余力矩 ESO 的三个离散误差极点公式与代码一致。创新具有累加作用，但线性模型的可观测性不会因角速度接近零而改变；不能据此把早期长尾超调写成已确认的可观测性问题。
- `Jαr`、`Bωr`、摩擦和已知负载在最终限幅前求和。ESO 使用上一周期最终命令或时间对齐的实际平均力矩；反算抗饱和也依据最终受限命令。新增前馈无需重复添加同一项。

这些核对支持保留现有结构。实测时序、模型参数与补偿启用条件仍决定效果，不能从公式成立直接推出实机性能。

## 正式代码修复

此前先触发 `BAD_TIMING`，随后以空反馈指针再次调用，会将锁存原因覆盖为 `BAD_ARGUMENT`，丢失最初的排查线索。现在先处理初始化状态和已锁存故障，再检查本次参数。初始化失败保持 `BAD_CONFIG`；有效初始化后保留第一个运行故障，直到显式复位。故障输出仍为零。

`tests/test_yaw_controller.c` 直接驱动真实 C 调用，覆盖后续空反馈、空参考、空输出、恢复正常参数、显式复位和初始化失败。旧实现的回归断言失败，正式修复通过。`YawReference.age_s` 注释同时改为“源采样距今的秒数”，避免将绝对时间戳误传为年龄。

## 反馈频率和传输延迟

原有公共性能仿真每 1 ms 产生新位置/速度，数据年龄为零；早期私有 Python 仿真的 500 Hz 设置不能当作公共 C 已覆盖的证据。现于 `sim/run_sensitivity.py::run_trial()` 追加两个默认关闭的选项：

- `feedback_period_samples=1`：采样间隔，以控制周期计。
- `feedback_delay_samples=0`：测量传输延迟，与命令延迟分别建模。

位置和速度同步采样，噪声仅在采样时抽取一次，量化后一起保持。读取旧样本不会刷新源时刻。初帧假设已在 t=0 同步，此后的样本按指定延迟到达；没有加入外推或重复样本去重。默认选项下，使用同一基线 C 库核对的 6001 行、原有 20 列轨迹逐位相同；新增最后一列 `feedback_age_s`。

`sim/run_feedback_timing.py` 固定两种电机 Yaw profile、2 Hz / ±5°、1 ms 控制周期、2 s 启动与 2–6 s 指标窗口。每种时序使用开发种子 4310–4312，每个种子仅切换补偿系数 `0/0.8`，积分及其他参数相同。共 60 次试验，包含已有协议量化、执行器滞后与命令延迟。

下表为三个种子的平均位置 RMSE，单位为度；数据来自[完整时序结果](evidence/algorithm_review_20261016/feedback_timing.json)。

| 反馈采样周期 / 传输延迟 | DM 补偿关闭 | DM 补偿开启 | GM 补偿关闭 | GM 补偿开启 | 最大数据年龄 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 ms / 0 ms | 0.10390 | 0.02581 | 0.02274 | 0.01622 | 0 ms |
| 2 ms / 0 ms | 0.10029 | 0.03104 | 0.02282 | 0.03673 | 1 ms |
| 1 ms / 2 ms | 0.12175 | 0.08745 | 0.08067 | 0.09723 | 2 ms |
| 2 ms / 2 ms | 0.13867 | 0.11502 | 0.10747 | 0.12381 | 3 ms |
| 2 ms / 5 ms | 超时锁存 | 超时锁存 | 超时锁存 | 超时锁存 | 6 ms |

前四种时序共 48 次试验没有锁存故障，GM 的后面三种仍出现补偿后误差增加。最后一种时序的 12 次试验均触发陈旧反馈保护；失效后的演化仍参与统计，JSON 保留首个故障、命令统计和大误差指标。**“仿真完成”只表示运行到终点，不代表控制性能通过。**

这个结果支持将真实反馈时序纳入 ESO 整定。`age` 合格仅说明数据未过期，不补偿相位滞后。不同采样周期下同一种子也不代表相同连续时间噪声；本矩阵不是新的独立留出集，未用于重新挑选带宽、补偿系数或性能门槛。Pitch、异步角度/陀螺更新、丢帧抖动与真实传感器滤波尚不在本新增矩阵内。

复现：

```bash
cmake --build build --parallel
python sim/run_feedback_timing.py --output build/feedback_timing.json
python -m unittest discover -s tests -p 'test_feedback_timing.py'
```

## 未采用的 ESO 数值候选

连续角度偏移到 1000 rad，零阻尼、零外扰、0.2 rad/s 匀速、1 ms 周期时，当前 float 绝对位置预测会引入虚假创新。局部增量候选采用：

```text
delta = h*z_velocity + 0.5*h*h*acceleration
innovation = (measurement - z_position) - delta
z_position += delta + L1*innovation
```

它与原公式在实数运算下等价；保留 float 状态、接口与全部参数。该确定性探针中，扰动估计 RMS 从 **0.006455 降至 0.001571 N·m**，速度偏置从 **0.011517 降至约 4.19e-8 rad/s**。正负偏移、正负速度、1/2 ms 周期及极小带宽均做了回归，详见[24 组探针记录](evidence/algorithm_review_20261016/precision_probe.json)。输入本身的 float 量化仍存在，不能宣称任意累计角度下精度不变。

**该候选未合并进正式观测器。** 完整重跑后，Yaw 门槛通过，DM Pitch 通过，但 GM Pitch 预定留出组相对同 Ki 原版的平均配对 RMSE 变化从原先的 −2.94%、4/5 改善变为 **−0.80%、3/5 改善**，未满足既定门槛。数值局部改善不足以支持整体采用；没有根据已看过的留出结果继续挑选算式或改动阈值。

保留[候选完整 Pitch 结果](evidence/algorithm_review_20261016/candidate_pitch_metrics.json)、[候选 Yaw 验收](evidence/algorithm_review_20261016/candidate_yaw_acceptance.json)及[候选补丁](evidence/algorithm_review_20261016/observer_precision_candidate.patch)。补丁以 `ce4c203` 为基线，包含当时的首因修复和数值回归，可在隔离 worktree 中复核；不应直接当作正式固件升级。候选报告的 C 源码 SHA-256 为 `32694d0e7739b218bc87a4bde891f146851e8baea9fe58d40cae74fc4e3cebc4`。

## 下一步优化依据

先采集真实控制周期、角度和陀螺的各自采样时刻、最终电机命令与补偿力矩，再分别评估模型、速度反馈、加速度前馈和 ESO 补偿。对 500 Hz 或有明显测量延迟的配置，应以补偿关闭作为实测对照，在开发数据上选取候选，并准备新的验证轨迹；不能直接沿用理想新鲜反馈仿真的参数。

继续保留当前 GM Pitch 合成开发组未通过、GM Yaw 收益含积分配置变化的边界。用户确认的 GM6020 Pitch 实机可用状态、截图中的 LQR + Kalman 实验、公共 C 内核的合成结果是不同证据；本次检查没有新增该公共内核的硬件 A/B 数据。
