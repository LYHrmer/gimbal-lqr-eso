# GM6020 电流模式接入

本模块提供独立 C 力矩换算、完整 CAN 电流组帧打包和反馈解析，不包含 CAN 驱动、模式切换、自动启动或硬件停止逻辑。用户尚未完成实物搭建，当前测试均为离线协议验证。

## 核对版本

依据 DJI / RoboMaster《GM6020 直流无刷电机使用说明》**v1.4，2023.10**，2026-09-08 核对。电流模式要求与命令见印刷页 6–7，反馈见印刷页 7，转矩常数见印刷页 11。PDF 包含封面，查看器页码分别为 7–8、8、12。[官方 v1.4 PDF](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E20231013.pdf)

手册要求电机固件 **≥ 1.0.11.2**，通过 **RoboMaster Assistant ≥ 2.7** 打开电流环。`gm6020_config_t.current_mode_confirmed` 表示上层已经核对实物配置；将它写成 `true` 本身不会配置电机。未确认时，即使请求零力矩，本模块也拒绝力矩编码。

## 两步生成电流命令

1. `gm6020_torque_to_word` 只转换一个电机的力矩，得到带 `valid` 标志的电流命令字及量化后的名义电流、名义力矩。它不生成 CAN 帧，也不知道电机 ID。
2. 上层集中管理同组全部电机的命令，形成完整快照，再调用 `gm6020_pack_current_group`。必须显式传入四个槽位和数量 `4`；模块不替缺少的电机补零。

| 电流组 CAN ID | 四个槽位的顺序 |
| --- | --- |
| `0x1FE` | 电机 1、2、3、4 |
| `0x2FE` | 电机 5、6、7、保留槽；最后一槽必须显式为 `0` |

这些是标准 CAN 数据帧，DLC 为 8，各槽位为大端有符号 16 位整数。电流命令 `±16384` 对应 `±3 A`。官方转矩常数为 **0.741 N·m/A**；本模块通过显式配置 `torque_constant_nm_a` 使用它，不从电机反馈中猜测。[电流协议与电机参数](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E20231013.pdf)

```text
名义请求电流 = 请求力矩 / Kt
名义电流 = raw × 3 / 16384 A
名义力矩 = 名义电流 × Kt
```

应用层独立指定 `current_limit_a` 和 `torque_limit_nm`，分别不得超过 3 A 和 `3 A × Kt`。转换先遵守这两个应用限额，再取最近的量化码；正好处于半格时向远离零方向舍入。如果量化跨过应用限额，会向内调整一格。输出 `limited` 标识发生应用限幅或边界向内调整。小于半格的请求可能量化为零。

取 `Kt=0.741` 时，协议电流端点对应名义 `2.223 N·m`，一格约 `0.0001356812 N·m`。这是命令映射推算，**不是电机已确认的峰值/持续力矩，也不保证实测轴端力矩等于该值**。该有符号协议能够精确编码软件零；仍不能把零命令当成驱动已失能或机械已停止。

## 完整组帧调用约定

以下是组帧数据流示意。`id1` 到 `id4` 必须来自对应电机本轮已成功的转换，零命令也需显式产生并纳入调度策略。

```c
/* 上层先核对四个 result == GM6020_OK、word.valid 以及命令时间戳。 */
int16_t slots[4] = {id1.raw, id2.raw, id3.raw, id4.raw};
gm6020_command_t command = {0};
gm6020_result_t result = gm6020_pack_current_group(
    0x1fe, slots, 4, all_current_modes_confirmed, &command);

if (result == GM6020_OK && command.valid && command.dlc == 8) {
    /* 交给上层总线调度器；经运行状态检查后才允许发送。 */
} else {
    /* 禁止发送 command.data，由上层处理转换/模式/调度故障。 */
}
```

单轴程序不能先清空整个 8 字节数组再只填写自己的位置，否则同组其它电机收到的命令也会改变。此模块提供完整组帧接口，让组内协调成为显式步骤；它本身不能保证调用者提供的其它槽位足够新鲜。需要一个共同的组帧调度者，以及明确的离线电机、过期命令和整组停止策略。

力矩转换失败会令 `word.valid=false`、名义值为 `NAN`，保留原命令字；组帧失败会令 `command.valid=false`、DLC 为 0、CAN ID 无效，保留原 payload。调用者必须检查返回码和有效位，禁止复用残留数据。函数没有电压模式后备路径，组帧函数也会拒绝电压组 ID。

## 反馈解释

`gm6020_decode_feedback` 接收已剥离 USB-CAN 外层封装的原始帧，检查标准数据帧、长度 8、电机 ID 1–7、期望 CAN ID `0x204 + motor_id`，并拒绝超出 `0..8191` 的编码器值。编码器单圈角度按 `raw × 2π/8192` 换算；转速按有符号 rpm 解析，再换算为 rad/s。

实际电流字段按有符号 16 位保存为 `current_raw`，温度字节保留为摄氏度数据。v1.4 反馈表没有明确该电流字段的 A/count 比例，因此不能照搬命令侧的 `3/16384`。如后续需要反馈电流或反馈力矩，应先通过匹配固件的说明或实测标定获得比例，记录来源，并在上层显式配置。当前模块不输出猜测的反馈安培数。

`feedback.valid=true` 只表示解析通过。角度展开、零位/方向校准、反馈时间戳、速度/温度保护、模式确认、停止策略和看门狗均由上层完成；反馈帧也没有被本模块虚构成统一的故障状态字。

## 电压协议版本边界

v1.4 的电压模式使用 `0x1FF / 0x2FF`，给定范围为 **±25000**。[v1.4 电压表](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E20231013.pdf) 旧版 v1.2（2020.05）写的是 **±30000**，不能混用版本范围。[官方 v1.2 PDF](https://rm-static.djicdn.com/tem/17348/RoboMaster%20GM6020%E7%9B%B4%E6%B5%81%E6%97%A0%E5%88%B7%E7%94%B5%E6%9C%BA%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E.pdf) 电压给定不能用一个固定 `Kt` 直接解释成力矩。本项目当前 **不提供电压控制 API**，不将电流命令发送到电压 ID。

## 离线验证

```sh
cc -std=c11 -Wall -Wextra -Werror -Wconversion -Wshadow -pedantic -O2 \
  -Iinclude src/gm6020.c tests/test_gm6020.c -lm -o /tmp/test_gm6020
/tmp/test_gm6020
```

测试包括 20001 个量化输入、正负端点、精确零、双重应用限额、未确认模式、非有限值、非法配置、完整组帧与保留槽、错误帧长/类型/ID、编码器边界、有符号 RPM/电流极值。测试断言需要启用，不能定义 `NDEBUG`。实现显式拒绝 `__FAST_MATH__` 编译，避免非有限数检查被优化掉。通过这些检查尚不能替代真实固件、接线及总线波形验证。
