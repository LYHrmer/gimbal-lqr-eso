# 源采样时刻驱动的 ESO 候选

本目录是离线算法试验，不加入 CMake 正式控制库，也不修改已有 profile。
`candidate.patch` 应用于本轮仿真代码的隔离副本；旧接口调用不带扩展元数据时保留原算法。

**本候选已被拒绝。** GM Pitch 同步 500 Hz 的平均配对 RMSE 增加 5.90%，
另有工况退化超过门槛；完整结果见 [诊断记录](../../docs/feedback_review_20261017.md)。
脚本保留该失败，复现时预期返回非零。

候选显式传入**位置**样本年龄、新样本标志、两次已接收位置样本的源时间间隔。
不能从 `YawFeedback.age_s=max(角度年龄,速度年龄)` 推断位置是否更新。
预测仍逐控制周期执行；重复位置样本不再校正。新样本的增益按源采样间隔计算。
对延迟位置，用当前预测的常加速度近似回推到采样时刻，再将校正量传播到当前时刻。
这不是完整的历史输入回放：延迟窗口内力矩、阻尼和扰动变化带来的误差仍存在。
位置与速度保持原始时间语义；状态反馈没有额外外推，陈旧输入保护仍生效。

运行前固定的开发筛选条件：

- 复用已声明的全部两轴时序工况、原参数和开发种子，不以新的留出验证命名。
- 补偿关闭时的 RMSE 与基线一致（容差 1e-12°）；新鲜同步反馈的补偿开启 RMSE 同样一致。
- 每个未超时工况的补偿开启平均配对 RMSE、峰值误差退化均不超过 5%。
- 两种 GM 轴在同步 500 Hz 和角度 500 Hz / 陀螺 1 kHz 工况的平均配对 RMSE 至少降低 10%。
- 不增加故障或物理越界；原超时案例仍锁存陈旧反馈故障。

条件未满足就保留失败证据，不进入正式控制器。即使满足，也只获得进一步验证资格，
还需完整既有验收、新的独立验证数据和 Cortex-M4F 运行耗时测量。

复现（先构建正常共享库）：

```bash
python3 sim/run_multirate.py --output build/multirate-baseline
python3 experimental/feedback_timing/run_candidate.py --baseline build/multirate-baseline/metrics.json --output build/multirate-candidate
```
