# GM6020 Pitch：保留 CAN 协议约束的 ESO 参数实验

本轮增加可复现的参数比较与验收检查，正式 C 控制内核、协议实现及控制参数保持不变。
全部结果是合成仿真；用户确认的 GM6020 Pitch 整机可用状态保留。私有整机源码没有进入仓库。

## 为什么保留原来的量化

GM6020 v1.4 规定反馈发送频率为 1 kHz，单帧同时包含机械角度和整数 RPM。
原 profile 的角度步长 `2π/8192 rad` 和速度步长 `2π/60 rad/s` 因此保留，
没有为了降低误差改小分辨率，也没有把电机 RPM 改称陀螺仪。
电流命令仍经现有 C 力矩编码器量化；`0x1FE/0x2FE` 组帧接口和应用限额保持原样，仿真不发送 CAN 帧。
协议依据及外部 IMU 边界见 [GM6020 接入](../../docs/gm6020_integration.md#反馈来源与仿真精度)。

新增 [配置检查工具](../../tools/check_motor_profiles.py) 校验两份电机配置的模式、ID、
应用限额和反馈量化，并编译生产 C 解码器验证相邻码步长。
DM 的步长从现有 PMAX/VMAX 映射推导；本轮没有改 DM 参数或引入新的反馈接口。
两份 profile 仅追加反馈来源说明，原 `sensor` 字段保持原位。

## 在运行前固定的方案

[plan.json](plan.json) 与 [脚本](run_experiment.py) 独立于原有 Pitch 验收。
比较对象是**当前新 C、重力开启、带宽 80 rad/s、补偿系数 0.8**；
这次比较参数配置，不用于替换原有“同 Ki 上游 / 新 C 重力关闭”对照的结论。

- 带宽 `40/60/80 rad/s` × 补偿系数 `0/0.4/0.8`，含当前配置共 9 组。
- 7 种工况：新鲜反馈、整帧延迟 2 ms、整帧延迟按 0/1/2 ms 循环、每第 4 次后续反馈整帧丢失、命令延迟 2 ms、惯量 ×0.75/×1.25。
- 所有工况的角度/RPM 共用同一个 CAN 采样和传输时钟，原生生产周期保持 1 ms。t=0 使用同步快照，随后应用延迟和丢帧；未模拟 CAN 仲裁、总线负载和驱动内部调度。
- 开发种子 5300–5302，共 **189 次**真实 C 闭环仿真；仍是已有开发种子，没有作为独立验证样本使用。
- 总长 6 s、控制周期 1 ms、中心 +20°、1 Hz / ±5°；2–6 s 评价跟踪，0–2 s 另外评价启动峰值。
- 仅 ESO 带宽和补偿系数改变。LQR、Ki、重力、力矩/变化率限制、测量噪声、协议量化和执行器滞后固定；每个工况的完整物理模型及 binary32 C 参数写入结果并校验。

开发筛选要求主工况平均配对 RMSE 至少改善 2%、3/3 种子改善、平均峰值误差不增加；
其余指标和工况的均值退化不超过 5%，包括启动峰值和命令 RMS。
所有计划轨迹均须完整、无锁存故障及物理边界越界。缺失/重复种子、非有限指标、模型或时钟漂移均不能通过。
“均值退化 ≤5%”不是每个种子都不退化，也不是全工况稳定性证明。

合格者按最差工况平均配对 RMSE 变化、主工况变化、候选 ID 依次排序。
选择与开发结果哈希先写入 `selection.json`，然后才可打开预留种子 6400–6419。
保留组只比较冻结的一个候选与基线，主工况至少 16/20 改善，其余门槛不变；
失败后不能换第二名继续试同一保留组。没有合格候选时不运行保留组。

## 本轮结果（2026-10-17）

主工况结果如下；RMSE 为三个种子的均值，百分比为逐种子配对变化的均值：

| 带宽 rad/s | 补偿系数 | RMSE（°） | 相对当前配置 | 改善种子 |
| ---: | ---: | ---: | ---: | ---: |
| 80（当前） | 0.8 | 0.028372 | 0% | 基线 |
| 60 | 0.8 | 0.030367 | +7.03% | 0/3 |
| 80 | 0.4 | 0.030766 | +8.43% | 0/3 |
| 60 | 0.4 | 0.032444 | +14.32% | 0/3 |
| 40 | 0.8 | 0.034166 | +20.41% | 0/3 |
| 40 | 0.4 | 0.034493 | +21.57% | 0/3 |
| 40 / 60 / 80 | 0 | 0.039205 | +38.19% | 均为 0/3 |

**没有可采用的候选，因此未打开新的保留组，正式参数保持 80 rad/s / 0.8。**
这只能说明本次固定网格内，降低带宽或补偿系数没有满足筛选条件，不能推断当前参数是全局最优。
补偿关闭时三种带宽的控制性能指标一致，表中合并展示不减少原始试验数。
这里的性能判断也不覆盖此前不同测量时序下补偿开启后退化的结果。

## 复现

先按 [快速开始](../../docs/quickstart.md) 构建 `build/libyaw_controller.so` 并安装 Python 依赖。
每次使用空输出目录，避免覆盖此前的计划、选择和证据。

```bash
python3 tools/check_motor_profiles.py --output build/motor-profile-contract.json
python3 experimental/pitch_eso/run_experiment.py --phase full --output build/pitch-eso-study
python3 -m unittest discover -s tests -p 'test_motor_profile_contract.py'
python3 -m unittest discover -s tests -p 'test_pitch_eso_study.py'
```

默认退出成功表示实验完成且来源未变，不表示性能筛选通过。
加 `--require-improvement` 可要求所选阶段的性能通过；当前方案预期返回非零，同时保留完整结果。
CI 运行开发矩阵和软件测试，不重复用保留组选择参数。

后续若使用 IMU，应先记录其真实来源、坐标、采样、滤波与延迟，再单独建立反馈模型；
若改变负载，应独立辨识 Pitch 的 J/B/重力。当前证据不支持直接替换实机参数。
